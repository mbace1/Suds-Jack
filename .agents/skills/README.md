# Suds-Jack agent skills

Canonical project skills live in `.claude/skills/` and are intentionally small, repo-specific operational rules.

## Codex and cross-agent discovery

Codex-style agents commonly discover project skills under `.agents/skills/`, while Claude Code discovers `.claude/skills/`. Do not fork the actual skill content into two independently maintained copies: `.claude/skills/` is the canonical source in this repository.

When operating through an agent that scans `.agents/skills/`, mirror or install the canonical Suds-Jack skills from `.claude/skills/` as part of the local workspace setup, preserving each `SKILL.md` verbatim. Never edit a mirrored copy without applying the same change to the canonical source.

Current canonical skills:
- `project-work-state`
- `game-playtest`
- `hub-release`
- `movement-regression`
- `godot-game-dev`
- `visual-reference-fidelity`

## Godot runtime tooling

For a local Godot workspace, prefer installing the `gda` skill generated by the installed `gda` version rather than vendoring a snapshot here. Its upstream guidance is version-locked to the installed CLI and supports runtime scene inspection, simulated input, screenshots, logs/errors, performance inspection, headless scene/script work and exports.

Project canon still wins over any external skill. `gda` is an execution/inspection surface, not design authority.

## Rule

Skills help an agent choose a process. They never replace proof. A playable claim still requires player-entry/runtime evidence; a visual-fidelity claim still requires comparison against the approved reference; a release claim still requires the Hub/deployed path to work.
